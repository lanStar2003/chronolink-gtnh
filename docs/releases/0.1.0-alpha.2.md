# GTNH 2.8.4 启动依赖修复

## 修复原因

alpha.1 错把 GT5-Unofficial 的发布构建号 `5.09.51.482` 写进 Forge 的依赖版本范围。
GTNH 2.8.4 对应 GT 在 `@Mod` 中向 Forge 登记的是 `MC1710`，这不是 Maven/JAR 发布构建号。
因此旧版会在启动时误报缺少 `gregtech [5.09.51.482,5.09.51.482]`。

## 改动

- Forge 依赖声明改为 `required-after:gregtech;required-after:CoFHCore`，保留必需依赖和加载顺序。
- 在 preInit 读取实际已安装 GT 的 `gregtech.GT_Version.VERSION`，独立核对 `5.09.51.482`。不会把编译时常量当作运行时版本，也没有泛化为“所有 GT 版本兼容”。
- 新增真实 Forge 版本解析器 + 官方 GT 开发/运行 JAR 的依赖回归检查；先复现 alpha.1 拒绝，再检验新成品 JAR 的声明和版本检查。
- 主分支成功构建的新版本自动发布 GitHub Release；只附加验证过的模组 JAR、校验文件和证据，不附带整合包依赖，不覆盖已发布版本。
- 保持简单单页面板，没有增加新的高级协议或界面。

## 安装

1. 退出游戏，移除 `chronolink-gtnh2.8.4-0.1.0-alpha.1.jar`，不要同时保留两个版本。
2. 下载本 Release 的 `chronolink-gtnh2.8.4-0.1.0-alpha.2.jar`，放进 GTNH 2.8.4 的 `mods`。
3. 不要替换或升级整合包的 GregTech，也不需要删除配置或存档。先用独立测试世界检查。

本版仍为 alpha：**依赖回归检查不是完整 GTNH 客户端/服务端启动，也不是实际机器传输或存档安全验证**。
具体构建结果见附件 `BUILD_EVIDENCE.json`、`DEPENDENCY_CHECK.txt`。
激光、数据光缆、AE 桥等高级协议仍未实现；EU/RF 独立记账。
